# 入力データの契約案（設計・開発者向け）

> 通常の入稿は [Illustrator 入稿と寸法資料](operator-intake.md) が正本です。Illustrator 担当は `.ai` と人向け寸法資料を渡し、note、material / placement JSON、XYZ 座標、回転行列を入力しません。本書の JSON、座標、配置は既存 builder と将来設計を説明する開発者向け契約です。

## 合意済みの入力運用

.aiの切断線・折り線・印刷を指定ルールに従ってレイヤー分けするなど、Illustrator上で事前に整理する運用は可能。未整理の任意の.aiをそのまま処理できることは初期要件にしない。

切断線と印刷は正しい位置で重なっているか、その状態に事前整理できる。Illustratorから専用の書き出し処理を実行する運用も許容する。形状・印刷・実寸情報を共通座標でまとめて書き出す方式を第一候補とするが、技術方式は未検証。

以下の具体的な規則は設計案。理想化サンプルで使う draft 規則は [入力サンプルの正本](../samples/idealized_input/input.json) として再生成可能に記録したが、実案件のレイヤー名・線種などを確定したものではない。

## 入力を分ける

| 入力 | 内容 | 決めるべきこと |
| --- | --- | --- |
| 展開図 | 外周、穴、折り線などの幾何 | パスの意味をどう識別するか |
| 印刷 | 表面・必要なら裏面の図柄 | 抽出方法、解像度、色管理 |
| 材料 | 紙厚、紙色、表面の見え方 | 単位と部材ごとの指定 |
| 配置指定 | 部材ごとの位置・向き、配置の基準 | 数値の入力形式、座標・基準点の規則 |
| 参考情報 | 完成写真、別の仕様書にある寸法 | 初期は人が参照し、配置値を入力する想定。自動読取は必須にしない |
| 将来の組み立て指定 | 折り方向・角度、接着など | 折り対応時に具体化する |

## 展開図の暫定規則

### 理想化サンプルの draft 規則

最初の検証は実案件データより先に、`samples/idealized_input/input.json` の理想化データで行う。単位は mm、部材ローカル原点はアートボード左上、+X は右、+Y は下とする。生成時には `X_ai = X_mm × 72 / 25.4`、`Y_ai = (artboard_height_mm - Y_mm) × 72 / 25.4` として Illustrator 座標へ変換する。

`PF_CUT` は閉じた外周と穴のストローク、`PF_PRINT_FRONT` は同じ部材ローカル座標の片面印刷、`PF_ANNOTATION` は形状生成から除外する注釈、`PF_FOLD` は将来用の空レイヤーとする。切断・印刷の各レイヤーには同じ `PF_PART_<部材ID>` 名のグループを置く。色だけを意味の根拠にせず、レイヤー名、グループ名、安定IDを併用する。

紙厚、部材寸法、穴、棚上面高さは JSON の明示入力を正本とする。厚み 3 mm と棚上面 120 / 240 / 360 mm は検証用の仮値であり、実案件の仕様と混同しない。組み立て配置や折り、両面印刷はこの段階で定義しない。

- 実寸と単位を明示する。内部の基準単位はmmを候補とする。
- 切断境界と印刷を分離する。色だけに意味を依存させるか、名前や専用出力を使うかは未決定。
- 外周と穴の境界は閉じたパスとして扱う案とする。微小な隙間の扱いは許容値を定めてから決める。
- 折り線は切断線と区別し、どの面同士を接続するかを導出または指定できるようにする。
- 寸法線、注釈、トンボなどは形状生成の対象外に指定できるようにする。
- 初期試作から複数部材に対応する。例の案件の.aiは、切り離される部材ごとに分かれていると思われるが、ユーザーの記憶に基づく暫定情報。ファイルと部材の対応、アートボード構成は実データで確認する。
- 初期試作で曲線の外周と穴に対応する。片面印刷を検証対象とし、表裏を別指定できるよう将来の両面印刷に配慮する。裏面指定がなければ紙の地色を使う案とする。

PDF互換.aiを受け付けることと、その内部からレイヤー名などの意味情報を取得できることは別の検証項目。初期は専用書き出しを第一候補とし、.ai直接読取を必須にしない。

## 配置の指定方針

フェーズ4で採用する配置入力、instanceと部材参照、ワールド座標、厚み基準、再生成・受け渡し・検証の詳細は[数値配置と編集可能な `.blend` 受け渡し設計](assembly-placement.md)を正本とする。

例の案件は平らな側面板・棚板・背面板・トップボードからなる。棚の高さは、別の仕様書に記載された「床から各棚の上面までの高さ」で決めていた。前後・左右の指定方法はユーザーから設計側に委ねられており、特定の接合や端合わせを案件の事実として固定しない。

部材ごとの位置・向きと、基準面や端を指定できる方式を候補とする。厚みを考慮して棚上面を指定高さに合わせる案を検証する。単位・軸・原点・回転順序・入力ファイル形式は未決定。仕様書から必要な数値を入力する運用は許容されている。

## 折りの指定方針（初期試作の後）

.aiには折り線の位置を入れ、山折り・谷折りと角度はBlender側で指定する方針。入力.aiへの方向・角度の事前記述は初期必須要件にしない。具体的な選択UIやAI経由の操作方法は未決定。

## 展開図以外に必要な値

最初に必要と考える値は、紙厚、単位、印刷面の向き、基準面。初期試作では部材ごとの配置値を与える。折り機能の追加時には各折り線の方向・角度が必要になる。裏面印刷、部材別の材料、接着関係、完成形の向きは案件に応じて追加する。

折り角度は「平面状態を0度とする」案。符号の意味は面の向きと折り軸の方向を定義してから確定する。山折り・谷折りは、どちらの面から見た呼称かを必ず指定する。

## 入力検査の案

外周の未閉鎖、自己交差、重複パス、孤立した折り線、微小面、単位不明、印刷との座標不一致を検出対象にする。処理不能な問題は位置と理由を示し、修正を促す。形状が変わる自動修復は、修復内容を確認できるものにする。
