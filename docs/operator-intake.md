# Illustrator 入稿と寸法資料

Blender オペレーターが、Illustrator オペレーターから受け取った `.ai` と寸法資料を agent に渡す。Illustrator オペレーターは通常のレイヤー、グループ、パス、名前の操作だけを行う。**path note、JSON、XYZ 座標、回転行列は入力しない。** 元の `.ai` は exporter が読み取り専用で開き、保存しない。

## `.ai` の入稿規則

1アートボードに対象の展開図を置く。レイヤーは `PF_CUT`、`PF_PRINT_FRONT`、`PF_FOLD` を作る。`PF_ANNOTATION` は任意で、寸法線、トンボ、作業メモを置ける。

各部材は、対象レイヤーの**直下**に `PF_PART_<部材名>` グループを作る。同じ部材の切断と印刷と折線には同じ部材名を使う。`PF_CUT` のグループには塗りなしの閉パスだけを置く。包含されない閉パスが1本だけ外周、外周に直接含まれる閉パスが穴になる。外周が複数、穴の入れ子、部材名の重複は診断して停止する。

`PF_FOLD` の同じ部材グループには、塗りなし・2アンカー・直線の開パスだけを置く。パス名は資料で参照する折線名（例 `FOLD_LEFT`）にする。空名はIllustrator DOM順に `FOLD_01`、`FOLD_02` と採番される。折線が外周に接続するか、穴や他の折線と交差しないか、面を分割できるかは次工程が診断する。

`PF_PRINT_FRONT` は見た目をPNGとして出力する。ライブ文字、複合パス、配置画像は切断形状にしないので、そのまま使える。これらと `PF_ANNOTATION` は切断検査から除外される。

## 寸法資料

PDF、寸法入り画像、完成写真、または自然文メモを同梱する。資料には次を記す。

- 単位と紙厚（例: `mm、3 mm`）
- 部材名と数量、完成時の対応
- 完成形の基準（どれが正面・上・裏か）と、寸法の基準（端、中心、表面、中央面のどれか）
- 部材同士の関係（接する辺、重なる/差し込む箇所、完成時の向き）
- 各折線名の山/谷、どちらの印刷面から見た呼称か、完成面間角、固定側/動く側、連鎖の根と順序

例: `単位mm、板厚3。正面は印刷面。BODYを根にし、FOLD_LEFTは印刷面側から谷、完成面間90°、BODY側を固定してLEFTを動かす。FOLD_TOPはLEFTの後に折る。棚の上面は床から120（上面基準）。`

角度は**完成後に折線を挟む2面が作る内角**として書く。資料が画像だけで読めない、又は矛盾するとき、agentは `FOLD_LEFT の山/谷と角度のどちらが正しいですか` のように部材名・折線名を示して聞き返す。全項目の承認を求める必要はない。

## 抽出IRと範囲

exporter は既存 `paper-fixture-illustrator-export-v1` に `parts[].folds[]` を追加する。各要素は `id`、`endpoints_mm`、`boundary_relation: "not-evaluated-by-intake"`、`status: "angle-and-direction-required-in-assembly-plan"` を持つ。これは抽出契約だけであり、折り生成、隣接面、山谷、角度、root、連鎖は後続工程の責務である。foldを含むexportを現行の平板builderへ渡して完成扱いにはしない。

## 提出前チェック

部材名と折線名が資料と一致し、`PF_CUT` に注釈がなく、外周と穴が閉じ、`PF_FOLD` が直線の開パスであることを確認する。agentは geometry overlay、print PNG、診断結果を返す。自動生成fixtureは契約検証用であり、ユーザー実案件を検証済みと示すものではない。
